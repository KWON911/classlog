# 학급요록 자동저장 설계

## 목표

학급기록의 학급요록 표에서 교사가 셀 값을 수정하면, 입력이 멈춘 뒤 변경된 학생 행만 자동으로 저장한다.

## 범위

- 텍스트 및 체크박스 셀 수정 후 800ms 동안 추가 수정이 없으면 자동 저장한다.
- 저장 요청은 현재 변경된 학생 행의 병합된 전체 `values`를 기존 `useYorokEntries.saveEntryValues`로 전달한다.
- 저장 중에는 `저장 중...`, 성공 후에는 `자동 저장됨`, 실패 시에는 오류와 재시도 가능한 변경 상태를 표시한다.
- 기존 `변경사항 저장` 버튼은 남겨, 대기 중인 변경을 즉시 저장하는 수단으로 사용한다.
- 컬럼 추가·삭제·이름 변경·순서 변경 및 기존 데이터 구조는 변경하지 않는다.

## 동작 설계

`YorokTable`은 현재처럼 학생별 draft와 dirty ID를 유지한다. draft 또는 dirty ID가 바뀌면 800ms 타이머를 설정하고, 타이머 만료 시점의 변경 학생 ID와 해당 draft 스냅샷을 저장한다. 추가 편집, 언마운트, 수동 저장 시작 시에는 이전 타이머를 취소한다.

저장 시작 시 해당 학생 ID만 저장 대상에서 분리해, 진행 중에 새로 편집한 값이 성공 처리로 잘못 지워지지 않게 한다. 성공한 ID만 dirty 상태에서 제거한다. 실패한 ID는 dirty 상태로 유지하고 오류 메시지를 보여 다음 자동 저장 또는 수동 저장으로 재시도할 수 있게 한다. 자동 저장 중 새 수정이 생기면 그 수정은 다음 디바운스 주기에서 저장한다.

## 오류 및 접근성

저장 상태 메시지는 `aria-live="polite"`로 읽힌다. 오류 메시지는 기존 한국어 문구 관례를 따르며, 저장 실패 때문에 사용자가 입력한 draft를 초기화하지 않는다.

## 검증

- 순수하게 추출 가능한 저장 대상 분리/결과 반영 로직은 Vitest로 테스트 우선 구현한다.
- 학급요록에서 텍스트 입력과 체크박스 변경이 800ms 후 저장되는지, 연속 입력이 단일 저장으로 합쳐지는지, 실패 후 재시도되는지 수동 확인한다.
- `npm test`, `npm run lint`, `npm run build`를 실행한다.
