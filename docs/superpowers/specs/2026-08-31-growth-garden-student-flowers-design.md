# 학생별 꽃 피움 설계

## 목표

성장정원의 학생 식물은 성장 점수와 기존 단계 기준을 그대로 따르며, 최종 단계에서만 학생마다 서로 다른 꽃을 피운다. 꽃은 교사나 학생이 선택하지 않고 자동 배정하며, 꽃봉오리 단계 전까지 종류를 알 수 없다.

## 배정 방식

`studentId` 문자열을 안정적인 정수 해시로 변환한 뒤 꽃 배열 길이로 나눈 나머지를 인덱스로 사용한다. 이 방식은 렌더링 중 `Math.random()`을 사용하지 않으며, 데이터베이스 스키마나 `BehaviorRecord`·`growthPoint` 데이터를 변경하지 않아도 새로고침과 화면 이동 후 같은 학생에게 같은 꽃을 반환한다.

학생 명단의 ID가 현재 프로젝트에서 화면과 서비스의 공통 식별자이므로, 별도 영구 저장보다 이 결정적 배정 방식이 기존 구조에 가장 적합하다.

## 성장 단계와 공개 규칙

- stage 0~4: 현재 씨앗·새싹·잎·줄기 형태를 공통으로 유지한다.
- stage 5: 모든 학생에게 같은 중립 꽃봉오리를 보여 준다. 꽃별 실루엣·색상·꽃잎은 드러내지 않는다.
- stage 6: 배정된 꽃 SVG만 렌더링한다. 꽃 이름 텍스트는 표시하지 않는다.
- 성장 점수 계산, 사용자 성장 기준 설정, 상벌점 기록은 변경하지 않는다.

## 꽃 SVG

기존 `PlantIllustration`의 단색 SVG, 둥근 선, 얇은 외곽선 없는 표현과 같은 시각 언어로 다음 여섯 종류를 추가한다.

- 튤립
- 해바라기
- 데이지
- 코스모스
- 장미
- 백합

서로 다른 꽃잎 수·실루엣·중심부·색상을 사용해 정원 및 전체화면에서 구별되도록 한다.

## 컴포넌트와 데이터 흐름

꽃 배정 순수 유틸리티는 `studentId`를 받아 꽃 종류를 반환한다. 공통 `PlantIllustration`은 선택적 `studentId` prop을 받고, stage 6에서 유틸리티가 고른 꽃 파트를 렌더링한다. 이전 화면 호환을 위해 `studentId`가 없는 호출은 기본 꽃을 사용한다.

학생 문맥을 이미 가진 카드, 정원 플롯, 학생 상세, 개인 월별 리포트, 월별 수상 축하 화면은 모두 `student.id`를 전달한다. 따라서 카드 보기·정원 보기·전체화면 정원·개인 리포트·특별 축하 화면에서 같은 학생은 동일한 꽃을 보여 준다.

## 검증

- 순수 배정 유틸리티가 같은 ID에 항상 같은 꽃을 반환하는지 테스트한다.
- 꽃 배열의 모든 항목이 유효한 꽃 종류인지 확인한다.
- `PlantIllustration` 호출부가 학생 문맥에서 `studentId`를 전달하는지 확인한다.
- TypeScript 검사, lint, production build를 실행한다.
