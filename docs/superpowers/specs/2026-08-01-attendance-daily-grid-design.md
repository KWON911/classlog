# 출결 일별 입력 목록을 그리드로 전환 설계

## 배경

`/attendance` 페이지 상단의 "선택한 날짜의 학생 전체 목록"이 학생당 한 줄(`<li>`)로 세로 나열되어 있어, 학생 수가 많을수록(예: 26명) 화면 세로 공간을 지나치게 많이 차지한다. 이 목록을 그리드 형태로 바꿔 한 화면에 더 많은 학생이 보이도록 하고, 아래에 있는 "학급 전체 요약" 표 등 다른 작업 영역을 가리지 않게 한다.

## 범위

**포함**
- 일별 입력 목록(`AttendancePage.tsx`의 현재 `<ul>...</ul>` 블록, 학생당 `<li>` 한 줄)을 그리드로 전환
- 그리드 셀은 "번호. 이름"만 표시하고, 그 날짜에 출결 예외가 있으면 이름을 빨간색으로 표시(출석은 기본 색), 상태·사유 텍스트는 셀에서 제거
- 학생 셀 클릭 시, 그리드 아래 고정된 한 자리에 "N. 이름 입력:" 레이블과 함께 상태/사유/메모 입력 폼(`AttendanceEditRow`)이 나타남
- 기존 `editingStudentId` 상태(한 번에 하나만 편집)를 그대로 재사용 — 렌더링 위치만 그리드 밖으로 이동

**제외**
- 하단의 "학급 전체 요약" 표(월별 카운트 + 이름 클릭 시 상세 기록 펼치기)는 이번 범위가 아님 — 변경 없음
- 그리드 셀 안에 상태 텍스트를 함께 표시하는 대안(사용자가 이름 색상만 표시하는 방식을 선택함)
- 그리드 열 개수를 사용자가 조절하는 설정 기능(반응형 브레이크포인트로 고정)

## UI

```
[1.구태리]  [2.김고은]  [3.김도윤]  [4.김태연]  [5.김태윤]  [6.김하윤]
(빨간색)
[7.도예준]  [8.박새봄]  ...

1. 구태리 입력:  [결석▼] [질병▼] [메모] [저장] [출석으로 되돌리기] [취소]
```

- 그리드는 기존 학급기록 목록(`StudentListPage.tsx`)의 `grid-cols-2 sm:grid-cols-3` 패턴을 참고하되, 셀 내용이 "번호. 이름"만 남아 훨씬 짧아지므로 더 촘촘한 `grid-cols-3 sm:grid-cols-4 md:grid-cols-6`을 쓴다.
- 각 셀은 버튼이며, 클릭 시 `editingStudentId`를 토글한다(이미 있는 로직 — `isEditing ? null : student.id`).
- 그리드 바로 아래에 입력 폼 영역을 하나 둔다. `editingStudentId`가 `null`이 아닐 때만 "N. 이름 입력:" 레이블과 `AttendanceEditRow`를 렌더링하고, `null`이면 이 영역 자체가 렌더링되지 않는다(현재와 동일하게 조건부 렌더링, 위치만 그리드 밖 고정 영역으로 이동).
- `AttendanceEditRow`에 전달하는 props(`initialStatus`, `initialReasonCategory`, `initialNote`, `onSave`, `onClear`, `onCancel`)는 변경하지 않는다 — 어떤 학생이 편집 중인지(`editingStudentId`)로 `entryByStudentAndDate`에서 해당 학생·날짜의 예외를 조회하는 로직도 그대로 재사용한다.
- 입력 폼 영역은 이 앱의 다른 폼 컨테이너(예: `StudentManagePage`의 학생 추가 폼, `rounded border border-gray-200 p-4`)와 동일한 스타일을 써서 그리드와 시각적으로 분리한다.

## 영향받는 코드

- `src/routes/AttendancePage.tsx`: 현재 165~198행의 `<ul>` 블록을 그리드 `<div>` + 별도의 고정 입력 영역으로 교체. `editingStudentId`, `entryByStudentAndDate`, `handleSave`, `handleClear` 등 기존 상태·핸들러는 변경 없음. 다른 파일은 건드리지 않는다.

## 테스트

이 페이지는 자동화 테스트가 없는 라우트 파일이라(기존 컨벤션), `npm run build` + `npm run lint` + 수동 스모크 테스트로 검증한다.

수동 확인 항목:
- 그리드가 여러 열로 표시되고, 그 날짜에 예외가 있는 학생만 이름이 빨간색으로 보이는지
- 학생 셀 클릭 → 그리드 아래 고정 영역에 해당 학생 이름과 입력 폼이 나타나는지, 다른 학생을 클릭하면 이전 학생의 폼이 닫히고 새 학생의 폼으로 바뀌는지
- 저장/취소/출석으로 되돌리기가 기존과 동일하게 동작하는지(로직 변경 없음이므로 회귀 없는지 확인 수준)
- 날짜/월을 이동했을 때 입력 폼이 닫히는 기존 동작(`editingStudentId` 초기화)이 그대로 유지되는지
