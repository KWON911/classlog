# 누가기록 작성 모드 디자인

## 목표

누가기록 폼을 연 교사가 `기록 추가`를 다시 누르는 혼동 없이 한 건을 저장하거나 취소할 수 있게 한다.

## 현재 문제

학생 상세의 누가기록 화면은 폼이 열린 뒤에도 상단의 파란 `기록 추가` 버튼을 유지한다. 폼 안의 실제 제출 버튼도 `추가`여서, 작성 중인 교사가 다시 상단 버튼을 누를 수 있다.

## 결정

- 폼이 닫힌 평상시에는 기존과 같이 도움말과 `기록 추가` 버튼을 표시한다.
- 폼이 열린 작성 모드에서는 상단 `기록 추가` 버튼을 클릭 불가한 `기록 작성 중` 상태 안내로 교체한다.
- 실제 동작 버튼은 폼 안에만 둔다. 제출 버튼 문구는 `기록 저장`, 보조 버튼 문구는 기존 `취소`를 유지한다.
- 저장 성공과 취소는 모두 기존처럼 폼을 닫고, 기록 추가만 저장 시 수행한다.

## 범위와 제약

- 학생별 한 건 작성 흐름만 개선하며, 연속 추가·모달 전환·데이터 모델 변경은 하지 않는다.
- 선택된 타임라인 카테고리를 새 기록 양식의 기본 카테고리로 넘기는 기존 동작을 보존한다.
- 키보드와 스크린 리더에서 안내 상태가 동작 버튼으로 읽히지 않게 한다.

## 검증

- 폼을 열면 `기록 추가` 버튼이 없고 `기록 작성 중` 안내와 `기록 저장` 버튼이 표시되는지 컴포넌트 테스트로 확인한다.
- 기존 카테고리 기본값과 도움말 테스트를 유지한다.
- 대상 Vitest, lint, production build를 실행한다.
