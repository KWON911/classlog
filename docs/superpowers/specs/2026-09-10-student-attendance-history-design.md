# 학생 누적 출결 이력 디자인

## 목표

누가기록의 학생별 출결 통계를 눌러 해당 상태의 전체 누적 이력을 조회하고, 원래 누가기록으로 한 번에 돌아갈 수 있게 한다.

## 동작

- 학생 상세의 결석·지각·조퇴·결과 통계 배지는 클릭 가능한 버튼으로 바꾼다.
- 클릭하면 `/attendance?student=<학생ID>&status=<상태>&view=history`로 이동한다.
- 출결관리의 이력 보기에는 학생 이름, 상태, 누적 건수, 날짜·상태·사유·메모 목록을 최신순으로 표시한다.
- 이력 보기의 `← 누가기록으로 돌아가기` 버튼은 `/students/<학생ID>`로 이동한다. 브라우저 뒤로 가기도 유지한다.
- 0건 배지는 버튼으로 만들지 않는다.

## 구조

- `useStudentAttendanceHistory` 훅이 RLS가 적용된 `attendance` 테이블에서 한 학생·한 상태의 전체 이력을 조회한다.
- `AttendancePage`는 URL 쿼리를 해석해 기존 일일/월간 화면 대신 이력 전용 컴포넌트를 렌더링한다.
- 학생 상세는 기존 `useAttendanceSummary` 값을 재사용하고 URL만 생성한다.

## 제약과 검증

- 출결 저장·삭제·NEIS 상태와 기존 일일·월간 화면 동작은 변경하지 않는다.
- 직접 Supabase 호출은 훅에서만 한다.
- 0건 비활성 상태, 올바른 이력 URL, 복귀 경로를 테스트한다.
- 대상 테스트, 전체 테스트, lint, production build를 실행한다.
