# 학급 성장정원 반복 성장 사이클 설계

## 목표

학생 식물의 `꽃 피움`이 마지막 목표가 되지 않도록, 꽃 이후의 성장과 다음 씨앗 사이클을 추가한다. 상벌점 기록과 누적 성장점수는 기존처럼 `growth_points`에서 파생하며 절대 초기화하지 않는다. 학생은 현재 식물을 계속 돌보고, 완성한 꽃은 꽃 도감에서 확인한다.

## 범위와 비범위

- 기존 카드·정원·전체화면·개인 상세·월별 리포트·수상 축하 화면에 현재 사이클 식물을 일관되게 표시한다.
- 교사나 학생이 꽃을 선택하는 UI, 희귀도·확률·점수 차등, 과거 꽃을 정원에 모두 누적 배치하는 UI는 만들지 않는다.
- 월간 성장값과 성장순, 상벌점·보상·수상의 관계는 바꾸지 않는다.

## 단계 및 설정

기존 0~6단계는 이름과 의미를 유지한다. 개인 식물 단계표 뒤에 다음 네 단계를 추가한다.

| 단계 | 이름 | 기본 기준 |
| --- | --- | --- |
| 6 | 꽃 피움 | 기존 기준 유지 |
| 7 | 생명체 방문 | 꽃 피움 + 5 |
| 8 | 결실 | 꽃 피움 + 10 |
| 9 | 풍성한 결실 | 꽃 피움 + 15 |
| 10 | 성장 완료 | 꽃 피움 + 20 |

- 기본 단계표는 `constants.ts`의 단일 소스에 둔다.
- `GrowthSettings.personal`은 새 11개 기준값을 저장한다. 기존 7개 값만 가진 저장 데이터는 앞 7개를 보존하고, 뒤 4개는 저장된 `꽃 피움` 기준에서 각각 +5, +10, +15, +20으로 채운다.
- 모든 기준은 0부터 시작하는 정수 오름차순이어야 한다. 기존 `validateThresholds` 규칙을 그대로 쓴다.
- 마지막 단계 기준은 한 성장 사이클의 완료 기준(`cycleCompletionThreshold`)이다. 컴포넌트에 점수를 하드코딩하지 않는다.

## 점수와 사이클 계산

`growth_points`와 `growth.ts`의 순수 집계는 source of truth로 유지한다.

```text
totalGrowthPoint = max(0, 상점 합계 - 벌점 합계)
cycleCompletionThreshold = 개인 단계표의 마지막 기준
completedCycles = floor(totalGrowthPoint / cycleCompletionThreshold)
currentCycleNumber = completedCycles + 1
currentCyclePoint = totalGrowthPoint % cycleCompletionThreshold
```

- 현재 식물의 단계는 `currentCyclePoint`와 같은 개인 단계표로 계산한다.
- 완료 기준의 정확한 배수(예: 45점)에서는 1번째 사이클을 완료하고 2번째 식물의 씨앗을 보여 준다.
- 벌점으로 현재 누적 점수가 줄면 현재 사이클의 단계는 내려갈 수 있다. 과거에 확정된 완료 이력은 삭제하거나 취소하지 않는다.
- 기존 학생도 현재 누적 점수로 완료 횟수와 현재 사이클을 즉시 계산한다. 예를 들어 92점, 완료 기준 45점이면 완료 2회·3번째 식물·현재 사이클 2점이다.

## 완료 이력과 기존 데이터 호환

새 `plant_cycles` 테이블과 서비스 계약을 추가한다. 한 행은 확정된 완료 사이클 하나를 나타낸다.

| 필드 | 의미 |
| --- | --- |
| `id` | 완료 이력 ID |
| `teacher_id` | RLS 소유자 |
| `student_id` | 학생 ID |
| `cycle_number` | 1부터 시작하는 완료 사이클 번호 |
| `flower_type` | 해당 사이클의 확정 꽃 종류 |
| `completed_at` | 완료를 감지한 시점 |
| `completion_threshold` | 완료 당시의 설정 기준 |

- `(teacher_id, student_id, cycle_number)` 고유 제약으로 중복 생성을 막는다.
- 기존 점수로 계산되는 완료분에 이력이 없으면, 화면 또는 훅이 필요한 누락 이력만 일괄 보정한다. 완료 시점은 실제 과거 시점을 추정하지 않고, 가장 관련 있는 과거 성장 기록 시각 또는 보정 시점으로 저장한다.
- 보정 꽃은 `studentId + cycleNumber` 결정적 배정으로 정한다. 따라서 새로고침과 화면 이동에 따라 바뀌지 않는다.
- 이후 완료분도 같은 고유 제약과 idempotent 생성으로 저장한다. 동시 저장·재렌더에도 같은 사이클이 두 번 기록되지 않는다.
- 교사가 완료 기준을 변경해도 이미 저장된 `plant_cycles` 행의 꽃·완료 시점·완료 당시 기준은 바꾸지 않는다. 새 기준은 현재 완료 횟수와 현재 식물 진행도 계산에만 적용한다.

## 꽃 배정과 도감

- `flowerForStudent`를 `studentId + cycleNumber`를 받는 순수 배정 함수로 확장한다.
- 현재 사이클의 꽃은 해당 키로 배정한다. 같은 학생이라도 사이클이 바뀌면 다른 결과를 낼 수 있고, 렌더 중 `Math.random()`은 사용하지 않는다.
- 직전 사이클의 꽃과 같으면 다음 배열 항목으로 한 칸 이동해 연속 중복을 피한다. 아직 완료한 꽃이 없는 첫 사이클은 기존 학생별 결정적 분포를 유지한다.
- 도감은 `plant_cycles`의 확정 이력을 시간·사이클 순으로 표시하고, 꽃 SVG 썸네일을 재사용한다. 현재 진행 사이클은 꽃 피움 전에는 물음표/중립 봉오리로, 꽃 피움 이후에는 현재 꽃 SVG로 표시한다.
- `FlowerType`과 메타데이터는 향후 rarity 같은 표시 전용 속성을 추가할 수 있게 한곳에 둔다. 이번 기능은 희귀도·보상 차등을 구현하지 않는다.

## 시각 표현

- stage 0~5는 현행 공통 식물과 중립 꽃봉오리를 유지한다.
- stage 6은 현재 사이클 꽃을 공개한다.
- stage 7은 꽃 주변에 제한적인 나비 또는 벌 한 마리와 아주 약한 흔들림을 표시한다. 카드에서는 무거운 개별 애니메이션을 만들지 않고 정원 보기와 학생 상세에서만 강조한다.
- stage 8은 꽃 종류별 결실 요소를 추가한다. 해바라기는 씨앗 중심부, 장미는 작은 열매, 튤립·백합은 씨앗주머니, 데이지·코스모스는 작은 씨앗 형태를 쓴다.
- stage 9는 결실 요소와 잎·꽃 일부를 더 풍성하게 하여 단순 확대가 아닌 성장 차이를 보인다.
- stage 10은 별도 장시간 화면으로 머물지 않는다. 완료 감지 후 짧은 반짝임 피드백을 보여 주고 다음 렌더에서 새 사이클의 씨앗으로 전환한다.
- 카드에는 현재 단계, `n번째 식물`, 다음 단계까지 남은 점수만 간결하게 표시한다. 정원·전체화면은 현재 사이클 식물만 표시한다.

## 화면별 데이터 흐름

- `GardenStudentCard`, `GardenPlot`, `GardenView`와 전체화면은 사이클 요약에서 얻은 현재 단계·사이클 번호·꽃을 `PlantIllustration`에 전달한다.
- `GrowthGardenStudentPage`는 누적 성장점수, 현재 사이클 번호·점수·진행도, 완료 횟수, 현재 식물과 꽃 도감을 제공한다.
- 월별 리포트는 월초/월말의 누적 점수로 각 시점의 사이클 요약을 계산한다. 사이클 번호가 증가하면 단계 숫자가 낮아져도 하락으로 보지 않고 `n번째 식물 완료 → n+1번째 식물 시작`으로 표시한다.
- `MonthlyAwardCelebration`은 현재 식물이 꽃 피움 이전이면 가장 최근 `plant_cycles`의 꽃을 대표 식물로 쓴다. 이력이 없으면 현재 식물을 사용한다.
- 학급 정원 환경과 월간 성장순은 기존 누적 점수·월간 순성장 계산을 그대로 사용한다.

## 서비스와 데이터 경계

- `GrowthGardenService` 또는 같은 서비스 계층에 사이클 이력 조회·누락 완료 이력 보정·생성 기능을 추가한다. UI는 Supabase를 직접 호출하지 않는다.
- Supabase와 mock 서비스 모두 같은 계약을 구현한다. mock은 localStorage에 이력을 보관한다.
- 새 migration은 `plant_cycles` 생성, 인덱스, RLS, 고유 제약을 추가하는 비파괴적 방식만 사용한다.
- 상벌점 저장 흐름은 기존 단일·일괄 `growth_points` insert를 유지한다. 기록 저장 성공 후 요약을 다시 계산해 필요한 완료 이력만 idempotent하게 보정한다.

## 검증

- 순수 사이클 계산: 0점, 꽃 기준, 완료 기준, 정확한 배수, 92점/45점, 벌점에 의한 현재 단계 하락을 테스트한다.
- 기존 7개 설정값 폴백과 11개 설정값 검증을 테스트한다.
- 학생·사이클별 꽃 배정의 안정성, 다음 사이클에서 직전 꽃 회피, 완료 이력 보정의 중복 방지를 테스트한다.
- `PlantIllustration`의 7~9단계 결실 표현과 현재 사이클 꽃 전달을 검증한다.
- 월별 리포트가 사이클 완료 후 새 씨앗을 하락으로 표현하지 않는지 테스트한다.
- TypeScript, lint, 전체 테스트, production build와 카드·정원·전체화면·상세·리포트·축하 화면의 수동 스모크 테스트를 실행한다.
